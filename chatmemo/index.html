개인정보처리방침

챗메모 (com.handfirst.chatmemo) · 개발자 FutureSoftLab · 시행일 2026년 11월 2일

챗메모는 대화하듯 말하면 AI 가 기억할 것을 메모로, 생일·약속을 날짜로 저장해 주는 앱입니다. 회원가입이 없고, 기기 고유 ID 로 사용자를 구분합니다. 대화·메모·날짜는 개발자 서버에 저장되며, 답을 만들기 위해 Anthropic(Claude API)으로 전송됩니다. 사진 백업은 기기에서 암호화된 상태로만 서버에 올라갑니다. 동영상은 기기 밖으로 나가지 않습니다. 화면 상단 배너 광고를 위해 Google AdMob 이 광고 식별자 등 기기 정보를 처리합니다.

1. 수집하는 정보와 목적

  • 기기 ID — 앱이 처음 켜질 때 Android 기기 ID(앱 서명키·기기·사용자 조합마다 다른 값)를 서버로 보내 사용자를 구분합니다. 가입·로그인 대신 쓰는 값이며 이름이나 전화번호와 연결하지 않습니다.
  • 대화 내용 — 폴더(대화방)에서 주고받은 글과 AI 의 답을 서버에 저장해 대화 화면에 보여 주고, 다음 답변의 맥락으로 씁니다.
  • 메모·날짜 — 대화에서 AI 가 저장했거나 사용자가 직접 쓴 메모(제목·내용·태그)와 날짜(생일·기념일·약속·마감, 음력 여부, 알림 시점). 메모·날짜 화면, 검색, 알림 계산에 씁니다. 사용자가 대화에 적은 내용(연락처, 비밀번호, 물건 위치 등)이 그대로 메모가 될 수 있으며, 개발자가 따로 요구하는 항목은 없습니다.
  • 폴더 — 폴더 이름과 이모지.
  • 사진 — 사용자가 대화에 보낸 사진은 서버에서 긴 변 1,280px 로 줄여 AI 에 한 번 보여 주고, 원본·축소본을 서버에 남기지 않습니다. 서버에는 AI 가 단 한 줄 설명·태그와 사진 크기만 남습니다. 사진 본체는 기기의 앱 전용 폴더(갤러리에 보이지 않음)에 저장되며, 설정에서 암호화를 켜면 AES-256-GCM 으로 암호화됩니다.
  • 사진 백업(암호문) — 기기를 바꿔도 사진을 되찾을 수 있도록, 기기가 사진을 사용자별 사진 키로 암호화한 뒤 서버에 올립니다. 서버는 암호문만 받습니다.
  • 사진 키·복구 코드 — 사진 키(32바이트)와 기기 변경용 복구 코드는 서버의 별도 마스터 키로 다시 암호화해 보관합니다. 복구 코드를 새 기기에 넣으면 같은 사용자로 이어집니다.

사진 키를 서버가 맡고 있으므로, 서버와 마스터 키를 함께 가진 개발자는 원리상 백업 사진을 복호화할 수 있습니다. 이 방식은 기기 분실·다른 앱의 접근·데이터베이스 유출로부터 사진을 보호하기 위한 것이며, 개발자는 백업 사진을 열람하지 않습니다.

기기에만 있는 정보 — 동영상, 잠금 패턴·PIN(PBKDF2 로 변환한 값을 기기 보안 저장소에 보관), 지문 정보(Android 가 처리하며 앱은 결과만 받음), 앱 설정. 이것들은 서버로 보내지 않습니다.

개발자는 이메일, 전화번호, 주소록, 정확한 위치를 요구하지도 저장하지도 않습니다.

2. AI 처리 (Anthropic)

대화 답변과 메모·날짜 저장 판단은 Anthropic, PBC 의 Claude API 가 만듭니다. 대화 한 번마다 개발자 서버가 보낸 글·사진, 그 폴더의 최근 대화, 최근 메모 제목, 다가오는 날짜, 검색이 필요할 때 찾은 메모를 Anthropic 으로 보냅니다 (앱이 직접 보내지 않으며 기기 ID 는 보내지 않습니다). Anthropic 은 개발자의 요청을 처리하는 수탁자로서 이 데이터를 받으며, API 로 받은 데이터를 모델 학습에 쓰지 않고 자체 정책에 따라 보관 후 삭제합니다 — Anthropic 개인정보처리방침. Anthropic 서버는 미국 등 국외에 있으므로 위 정보는 국외로 전송됩니다.

3. 광고 (Google AdMob)

이 앱은 화면 상단에 Google AdMob 배너 광고를 표시합니다. 광고를 게재하기 위해 AdMob 이 다음 정보를 처리할 수 있습니다.

  • 광고 식별자(Advertising ID) 등 기기 식별자
  • 기기 정보(기종, 운영체제 버전 등)와 대략적인 위치(IP 주소 기반)
  • 광고 노출·클릭 기록
  • 광고 SDK 의 비정상 종료 로그 및 진단 정보

이 정보는 개발자가 아니라 Google 이 직접 수집·처리하며, 개발자 서버로 오지 않습니다. 대화·메모·날짜·사진은 AdMob 에 제공하지 않습니다. Google 의 데이터 처리 방식은 Google 의 파트너 사이트 정책에서 확인할 수 있으며, Google 서버가 국외에 있으므로 국외로 전송될 수 있습니다. 유럽경제지역(EEA)·영국·스위스에서는 광고를 불러오기 전에 Google 의 동의 화면이 먼저 뜨고, 거부하면 비맞춤 광고만 표시됩니다. 맞춤 광고를 원하지 않으시면 기기 설정에서 끌 수 있습니다.
설정 → Google → 광고 → 광고 ID 삭제 (기기에 따라 "광고 개인 최적화 선택 해제")

앱에 인앱 결제는 없습니다.

4. 요청하는 권한

  • INTERNET · ACCESS_NETWORK_STATE — 서버와 대화하고 광고를 불러올 때 씁니다.
  • POST_NOTIFICATIONS · RECEIVE_BOOT_COMPLETED · WAKE_LOCK — 생일·약속 알림을 띄우고, 기기를 다시 켠 뒤에도 알림을 다시 걸 때 씁니다. 알림은 기기 안에서 예약되며 서버가 푸시를 보내지 않습니다.
  • USE_BIOMETRIC · USE_FINGERPRINT — 잠금을 지문으로 풀 때만 씁니다. 지문 자체는 앱이 받지 않습니다.
  • com.google.android.gms.permission.AD_ID 및 광고 관련 권한(ACCESS_ADSERVICES_*) — 광고 게재를 위해 AdMob 이 사용합니다.

사진·동영상은 Android 의 사진 선택기, 파일 선택기, 기본 카메라 앱을 통해 사용자가 고른 것만 받습니다. 앨범 전체 접근, 위치, 연락처, 마이크 권한은 사용하지 않습니다.

5. 제3자 제공

개발자가 사용자 정보를 판매하거나 마케팅 목적으로 제3자에게 제공하는 일은 없습니다. AI 처리를 위해 Anthropic 에(2항), 광고 게재를 위해 Google AdMob 이(3항) 위 정보를 처리합니다. 분석 도구, 소셜 로그인, 결제 모듈은 넣지 않았습니다.

6. 보관 기간

대화·메모·날짜·사진 설명·사진 백업(암호문)·사진 키는 사용자가 앱을 쓰는 동안 서버(대한민국 AWS 서울 리전)에 보관하며, 삭제를 요청하면 지웁니다. 메모·날짜·사진은 앱에서 하나씩 지울 수 있고, 폴더를 지우면 그 폴더의 대화·메모·날짜·사진 기록과 백업이 함께 지워집니다. 앱을 지워도 서버의 기록은 남으며, 같은 기기에 다시 설치하거나 새 기기에 복구 코드를 넣으면 이어집니다.
